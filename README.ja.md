# Xtrifid

小物や人物を文章で指定し、GTK の 3D ビューでメッシュを確認しながら部品ごとに修正できます。形状はメートル単位で編集できる静的モデルです。画面の表示言語はロシア語です。

## Linux 用実行ファイル

glibc 2.39 以降、グラフィカルデスクトップ、OpenGL 3.3 を備えた x86-64 Linux 用の実行ファイルです。Linux Mint 22 と Ubuntu 24.04 はこの要件を満たします。Python、GTK、CPU 版の Ollama を同梱しています。 [Linux 版 Xtrifid をダウンロード](https://github.com/glitchykid/xtrifid/releases/latest/download/xtrifid-linux-x86_64)

ダウンロード先で次のコマンドを実行します。実行権限を付けた後はダブルクリックでも起動できます。

```sh
chmod +x ./xtrifid-linux-x86_64
./xtrifid-linux-x86_64
```

保存したプロジェクトのパスを引数に渡すと、プロジェクトごとに別のウィンドウで開きます。プレビュー、数値による編集、OBJ の書き出しはオフラインでも使えます。

```sh
./xtrifid-linux-x86_64 "model.xtri"
```

複雑な指示や文章による編集には、Linux 上の Xtrifid の Docker サービスを含め、動作中のローカル Ollama を探します。見つからなければ内蔵 CPU エンジンを起動します。最初のリクエストで重みが足りない場合は **Скачать модель** で `qwen3.5:4b`（約 3.3 GB）をダウンロードし、もう一度リクエストしてください。内蔵エンジンは重みを `~/.ollama/models` に保存し、以後はオフラインで利用できます。保存先は `OLLAMA_MODELS`、接続先は `OLLAMA_URL`、構造化出力に対応するモデルは `XTRIFID_MODEL` で指定できます。

## Docker でソースから起動する

Docker Engine と Compose、Git、`xauth`、OpenGL 3.3 に対応する X11 または XWayland のデスクトップが必要です。Mesa のソフトウェアレンダリングにも対応しています。初回はコンテナを取得します。自由文から生成するにはモデルの重みも必要です（Qwen は約 3.3 GB）。メモリ 16 GB の CPU 環境で動作を確認しました。

```sh
git clone https://github.com/glitchykid/xtrifid.git
cd xtrifid
./studio
```

スクリプトは Ollama を起動してスタジオを開きます。重みを求められたら **Скачать модель** を押してください。次回からは Docker ボリュームに保存した重みを使います。入力した文章はローカルの Docker ネットワーク内で処理されます。構造化出力に対応した別の Ollama モデルを使う場合は、`./studio` の実行前に `XTRIFID_MODEL` を設定します。サービスの停止には `docker compose down` を使います。

## モデルの生成と修正

1. 形状、寸法、部品の接し方を文章で指定します。例えば円形の鏡面と楕円形の台座を持つ卓上鏡を頼めます。重みを使わずに試すには `make a person` と入力します。 **Game Ready** または **Для рендера** を選び、**Детализация** で **Низкая**（低）、**Средняя**（中）、**Высокая**（高）のいずれかを指定して **Создать модель** を押します。
2. ドラッグで回転、スクロールで拡大縮小、クリックで部品を選択します。**Сетка** で辺を表示します。**К детали**（F）は選択部品、**К лицу** は人物の顔を拡大します。Home で全体表示に戻り、矢印キーで回転できます。
3. 寸法、位置、回転角を変更して **Применить значения** を押します。人物では **Анатомия и поза** を開き、成人の体型（中性・男性・女性）や姿勢を選び、耳、鼻、唇、あごなどの大きさを調整して **Применить к телу** を押します。**Изменить деталь** で文章による修正、**Отменить действие** で取り消しができます。
4. **Сохранить** は編集可能な `.xtri` を保存し、**Открыть** はそれを開きます。**Экспорт OBJ** は現在のメッシュを書き出します。実行ファイルでは選んだフォルダーに直接保存します。Docker では `/exports` を選ぶとホストの `./exports` に保存されます。

## 一つの角やリングを修正する

部品を選んで **Контур детали** を開きます。断面図の点をクリックするか、**Вершина** で番号を選ぶと、対応する辺、リング、極点が 3D ビューで強調されます。点をドラッグするほか、メートル単位のローカル座標を 2 つ入力して **Применить координаты** を押すか、「この点の半径を 5 mm 増やし、高さはそのまま」のように指示できます。

直方体と押し出し形状では、ローカル XY 平面の点が垂直な辺を決めます。円柱、円錐、管、回転体では半径と Z 座標でリングまたは極点を指定します。初回の修正でプリミティブは押し出し形状または回転体に変換されます。他の制御点の空間位置は保持され、外形が変わると部品の中心が再計算されます。取り消しで元の形に戻せます。楕円体とトーラスは部品単位で編集できます。既存の XTRI プロジェクトもそのまま開けます。

曲面状の部品では **Поперечные сечения** を開きます。輪を選び、高さ、X・Yの半径、中心をメートルで指定して **Применить сечение** を押します。他の輪の位置を保ったまま、強調表示された輪だけが変わります。

## メッシュのプロファイル

| プロファイル | 形状 |
| --- | --- |
| Game Ready | 面の向きをそろえた三角形メッシュ。円周の分割数は低・中・高の順に 8、16、32 です。直方体は 8 頂点、12 三角形です。 |
| Для рендера | 円周の分割数は 24、48、64 です。規則的な面では四角形の列を保持し、極や縁、複雑な端面には必要に応じて三角形を使います。 |

ローカル言語モデルは最大48個の名前付き部品を組み合わせ、高さに応じて中心や径が変わる楕円断面で曲面を構成できます。寸法と支持関係から部品を配置します。未知の物体では生成後に形を調整することがあります。

成人の人体には MakeHuman の解剖学的メッシュを使っています。耳、唇、まぶた、指、胴体は連続した皮膚のメッシュで、眼球は別の形状です。人物だけを指定すると裸の人体を生成します。マントやフードは明示してください。体を選択すると体型を調整できます。OBJ にはマテリアルやアニメーション用リグを含まない静的形状が保存されます。

## 詳細度とリソース

詳細度は低・中・高から選びます。人物には2つのプロファイルで計6段階のメッシュがあり、選択はプロジェクトに保存されます。バージョン1と2のファイルも開けます。基本の人物はオフラインで生成でき、自由記述と文章による修正には Ollama の重みが必要です。

編集可能な作例 · [人物](https://github.com/glitchykid/xtrifid/releases/download/v0.5.0/human.xtri) · [マウスの外装](https://github.com/glitchykid/xtrifid/releases/download/v0.5.0/mouse-shell.xtri) · [卓上鏡](https://github.com/glitchykid/xtrifid/releases/download/v0.5.0/table-mirror.xtri)

プレビューや書き出しの前に、空きメモリと Linux コンテナの制限から三角形数の上限を計算します。デスクトップ用の余裕を確保し、1 シーンの上限を三角形換算で 150,000 に制限します。選んだ詳細度で収まらない場合は前のモデルが残ります。詳細度を下げるか Game Ready を選んでください。保存ファイルを開く際は利用可能な詳細度を選び直せます。推論側でもモデルサイズ、CPU スレッド数、コンテキスト長を制限します。他のアプリの負荷もシステムに影響します。

## 問題が起きたとき

- **実行ファイルが開かない。** 実行権限、グラフィカルセッション、`ldd --version` で glibc のバージョンを確認してください。必要な `GLIBC` のバージョンがない場合は、上記の Docker 手順を利用できます。
- **重みのダウンロードが中断した。** サーバーの空き容量とインターネット接続を確認してください。TLS エラーの場合はサーバーで信頼されている CA 証明書も確認し、再度 **Скачать модель** を押してください。CPU での初回生成には数分かかることがあります。
- **Docker** · **プレビューが黒い、または `MESA: error: Failed to attach to x11 shm` が表示される。** Git で取得した場合は `git pull --ff-only` を実行してから、もう一度 `./studio` を起動してください。アーカイブを使う場合は 0.2.1 以降を使用してください。起動時にイメージが再ビルドされ、Docker の共有メモリが分離された環境でも Mesa が画面を表示できます。
- **Docker** · **ウィンドウが開かない。** デスクトップの端末から起動し、`echo "$DISPLAY"` と `xauth info` を確認してください。スクリプトは現在のディスプレイの認証 cookie を渡します。
- **Docker** · **Ollama のエラー、初回の応答が遅い。** `docker compose logs --tail 40 ollama` と `docker compose exec ollama ollama list` を確認してください。CPU での初回読み込みには時間がかかります。失敗時も直前のシーンは保持されます。
- **意図した形にならない。** 個数、単位、接する箇所を指定し、輪郭とメッシュを確認してから部品を選んで修正してください。

問題を報告する際は入力文、プロファイル、再現手順を添えてください。[GitHub Issues](https://github.com/glitchykid/xtrifid/issues) · [設計と Docker テスト](docs/architecture.md)
