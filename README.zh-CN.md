# Xtrifid

在 GTK 中根据文字或参考图片创建可编辑的 3D 模型。可以检查网格，模拟布料、毛发和液体，并为各部件设置材质和表面凹凸。长度单位为米，界面语言为俄语。

Xtrifid 0.7.0 提供八个可编辑的 Game Ready 示例，包括月之剑、复古光能枪、仪仗手枪、孔雀羽扇、沼泽怪兽、提灯、环轨法术和破碎的海浪。打开任意 `.xtri` 文件即可修改各部件的形状和材质。 [查看模型](https://github.com/glitchykid/xtrifid/blob/main/examples/art-studies/gallery.jpg) · [下载 XTRI 和 GLB 文件](https://github.com/glitchykid/xtrifid/releases/download/art-studies-1/xtrifid-art-studies.zip)

## Linux 可执行文件

此文件适用于 x86-64 Linux，需要 glibc 2.39 或更高版本、图形桌面和 OpenGL 3.3。Linux Mint 22 和 Ubuntu 24.04 满足发行版要求。文件中已包含 Python、GTK 和 CPU 版 Ollama。 [下载 Linux 版 Xtrifid](https://github.com/glitchykid/xtrifid/releases/latest/download/xtrifid-linux-x86_64)

在下载目录运行以下命令。赋予执行权限后，也可以双击文件启动。

```sh
chmod +x ./xtrifid-linux-x86_64
./xtrifid-linux-x86_64
```

启动时传入已保存工程的路径即可直接打开，每个工程使用独立窗口。预览、数值编辑和 OBJ 或 GLB 导出均可离线使用。

```sh
./xtrifid-linux-x86_64 "model.xtri"
```

对于复杂描述和文字修改，程序会查找本机运行的 Ollama，包括 Linux 上 Xtrifid 的 Docker 服务。如果找不到服务，就启动内置 CPU 引擎。若首次请求时缺少权重，请点击 **Скачать модель** 下载 `qwen3.5:4b`（约 3.3 GB），然后再次提交请求。内置引擎将权重保存在 `~/.ollama/models`，之后即可离线生成。可用 `OLLAMA_MODELS` 更换权重目录，用 `OLLAMA_URL` 指定服务器，或用 `XTRIFID_MODEL` 选择支持结构化输出的模型。

## 从源码通过 Docker 运行

需要 Docker Engine、Compose、Git、`xauth`，以及支持 OpenGL 3.3 的 X11 或 XWayland 桌面。也可以使用 Mesa 软件渲染。首次运行会下载容器镜像。自由描述生成还需要模型权重（Qwen 约 3.3 GB）。已在配备 16 GB 内存的 CPU 环境中验证。

```sh
git clone https://github.com/glitchykid/xtrifid.git
cd xtrifid
./studio
```

脚本会启动 Ollama 并打开工作室。提示需要权重时，请点击 **Скачать модель**。随后会复用 Docker 卷中的权重。输入的描述留在本地 Docker 网络内。若要改用支持结构化输出的其他 Ollama 模型，请在执行 `./studio` 前设置 `XTRIFID_MODEL`。执行 `docker compose down` 即可停止服务。

## 创建与修改

1. 描述形状、尺寸和部件的连接方式。例如，可以要求制作一面带有圆形镜面和椭圆形底座的台镜。首次离线试用可输入 `make a person`。 选择 **Game Ready** 或 **Для рендера**，然后在 **Детализация** 中选择 **Низкая**（低）、**Средняя**（中）或 **Высокая**（高）。点击 **Создать модель**。
2. 拖动旋转，滚动缩放，点击选择部件。**Сетка** 显示网格边线。**К детали**（F）放大所选部件，**К лицу** 显示人物面部特写，Home 恢复全景，方向键旋转视图。
3. 更改部件尺寸、位置或旋转角后点击 **Применить значения**。选择人体，展开 **Анатомия и поза**，选择中性、男性或女性成人体型及姿势，也可调整耳、鼻、唇、下巴等局部比例，再点击 **Применить к телу**。**Изменить деталь** 应用文字修改，**Отменить действие** 撤销上一步。
4. **Сохранить** 保存可继续编辑的 `.xtri` 工程，**Открыть** 打开工程，**Экспорт OBJ** 导出当前网格。运行可执行文件时，文件会直接保存到所选目录。在 Docker 中选择 `/exports`，即可在宿主机的 `./exports` 中找到文件。

## 形状和表面

**Low Poly** 可独立于网格用途和精度选择。勾选后，曲面部件的分段数减少，显示平面着色。取消勾选恢复平滑显示。平面和已烘焙帧保留原有拓扑。配置表中的分段数适用于标准风格。

要制作分枝有机体，可描述主干、分枝的数量、粗细和延伸方向，例如有三根逐渐变细的分枝的珊瑚。在 **Узлы формы** 中按名称选择节点，调整其局部位置或半径。各分枝连接成一个封闭表面。

## 模拟

选择承托部件，展开 **Физика**，可选择布料、毛发、水面或体积液体。布料会垂落在选中的物体上，选中披风时肩部保持固定。毛发的根部固定。水面模式计算矩形水池中的波动，体积液体模式模拟一团液体在重力作用下落到物体上并散开。

设置风力和重力，点击 **Воспроизвести** 播放，可暂停或在六秒时间线（180 步）上选帧。点击 **Запечь кадр в модель** 将当前几何体存入工程，之后可以导出 OBJ。披风会替换为变形后的网格，其他效果会添加为独立部件，可撤销。碰撞使用简化形体，播放速度取决于精度和 CPU。关闭工程前请烘焙需要保留的帧。

## Game Ready 材质

选中部件并展开 **Текстура детали**，从木材、石材、织物、皮肤或皮革、金属、涂层中选择一种，设置配色、图案、缩放、随机种子与分辨率（128 至 1024 像素）。点击 **Назначить** 即可离线生成贴图，**Новый вариант** 会更换种子。**Создать по описанию (ИИ)** 使用本地 Ollama 解读“带细小划痕的抛光黄铜”等描述。生成参数保存在工程中，之后可以修改。

Game Ready 默认为新材质启用 **PBR-материал**。设置 **Шероховатость**（粗糙度，0–1）、**Металличность**（金属度，0–1）和 **Сила рельефа**（法线强度，0–2），然后点击 **Назначить**。强度为零时生成平坦法线贴图。预览光照会呈现织物纹路、毛孔或木纹。模型轮廓和三角形数量保持不变。也可为之前保存的纯色彩贴图启用 PBR。

Game Ready 的 **Экспорт GLB** 将索引三角形、UV、切线和贴图写入同一个文件。基础颜色使用 sRGB，切线空间法线贴图采用 OpenGL +Y 约定。线性贴图的绿色通道保存粗糙度，蓝色通道保存金属度。移动 OBJ 时请同时复制旁边的 `xtrifid-materials-…` 目录。游戏用 OBJ 分别输出 PBR 部件的法线、粗糙度和金属度 PNG。如果导入器只读取了 MTL 的颜色，请把这三张贴图指定为非颜色（Non-Color）数据。渲染用 OBJ 保留颜色贴图和四边形面。

[三种材质的 GLB](https://github.com/glitchykid/xtrifid/releases/download/v0.7.0/material-study.glb) · [可编辑工程](https://github.com/glitchykid/xtrifid/releases/download/v0.7.0/material-study.xtri)

## 根据参考图片生成模型

选择精度后点击 **По референсам…**。在 **Силуэты** 中载入正面 PNG 或 JPEG，也可以添加同一物体的右视图。请使用透明或纯色背景的正投影视图。白色预览表示提取出的轮廓。以米为单位设置高度，第二个视图按比例确定深度。只有一个视图时默认深度为宽度的 55%，可手动更改。圆弧形物体可以启用 **Округлить сечения**，估算圆滑的横截面和细小凸起的厚度。在 **Силуэты модели** 中用画笔增加或擦除区域，再点击 **Применить силуэты** 重建体积。

普通照片可选择 **Фото с ИИ**。缩小后的图片会交给所选的 Ollama 视觉模型，按可见物体生成近似的可编辑场景。可以用文字指明主体，隐藏的表面由模型推测。轮廓模式无需模型权重或网络。单张图片上限为 16 MiB、2400 万像素。在 Docker 中请把图片放进主机的 `exports/`，然后在应用的 `/exports` 中选择。 浓缩咖啡示例保留了杯柄的通孔，勺头的凹面被近似为扁平的椭圆。 [照片、工程和 OBJ](https://github.com/glitchykid/xtrifid/releases/download/v0.6.0/photo-example.zip)

## 单独修改一个角或圆环

选中部件后展开 **Контур детали**。点击截面图上的点，或在 **Вершина** 中选取编号，3D 视图会高亮对应的棱边、圆环或极点。可以拖动该点，输入两个以米为单位的局部坐标后点击 **Применить координаты**，也可以输入“将这个点的半径增加 5 毫米，高度保持不变”。

长方体和拉伸体的截面点控制局部 XY 平面上的一条竖直棱边。圆柱、圆锥、管件和旋转体的截面点通过半径和 Z 坐标控制一个圆环或极点。首次修改会将基本体转换为拉伸体或旋转体。其余控制点保持原来的空间位置，部件中心会随外形边界重新计算。撤销可恢复原形。椭球和圆环体支持整体编辑。已有的 XTRI 工程可直接打开。

对于曲面外壳，展开 **Поперечные сечения** 并选择一个环。以米为单位设置高度、X/Y 半径或中心位置，然后点击 **Применить сечение**。只有高亮环发生变化，其他环保持原位。

## 网格配置

| 配置 | 网格 |
| --- | --- |
| Game Ready | 输出绕序一致的三角面。圆周在低、中、高精度下分别分为 8、16、32 段。长方体使用 8 个顶点和 12 个三角面。 |
| Для рендера | 圆周分别分为 24、48、64 段。规则曲面保留连续四边面，极点、边缘和复杂端盖等位置按需使用三角面。 |

本地语言模型最多可组合 48 个命名部件。它能用沿高度偏移、扩张或收缩的椭圆截面构建曲面外壳，根据尺寸和支撑关系摆放部件。对于不熟悉的物体，生成后可能需要修正外形。

成人人体采用 MakeHuman 解剖网格。耳、唇、眼睑、手指与躯干的皮肤是连续的，眼球有独立的几何形体。仅输入人物时会生成无衣物的人体。需要披风或兜帽时请明确说明。选中身体可调整比例。可以为身体和每件衣物分别指定材质。

## 精度与系统资源

请自行选择低、中或高细节。两种网格配置共提供六种人体网格密度，工程会记住所选级别。包含 PBR 材质或已烘焙布料 UV 的工程使用 XTRI 格式 5，其余工程使用格式 4。可读取格式 1 至 5。基本人体命令可离线使用，自由描述和文字修改需要 Ollama 权重。

预览或导出前，Xtrifid 会根据可用内存和 Linux 容器限制估算三角面预算，并为桌面预留内存。场景三角化后上限为 150,000 个三角面。所选精度超出预算时会保留原有场景。可降低精度或改用 Game Ready。打开已保存工程时，也可以确认使用较低的可用精度。推理另有限制，包括模型大小、CPU 线程数和上下文长度。其他程序的负载也会影响整个系统。

## 常见问题

- **可执行文件无法打开。** 检查执行权限和图形会话，并用 `ldd --version` 查看 glibc 版本。如果系统提示缺少所需的 `GLIBC` 版本，请使用上面的 Docker 运行方式。
- **权重下载中断。** 检查服务器的可用磁盘空间和网络连接。如果提示 TLS 错误，还需检查服务器系统信任的 CA 证书。然后再次点击 **Скачать модель**。CPU 首次生成可能需要几分钟。
- **Docker** · **预览黑屏或出现 `MESA: error: Failed to attach to x11 shm`。** 如果通过 Git 安装，请运行 `git pull --ff-only`，然后重新运行 `./studio`。如果使用源码压缩包，请下载 0.2.1 或更新版本。启动脚本会重新构建镜像，更新后的 Mesa 驱动可以在 Docker 共享内存隔离的情况下显示画面。
- **Docker** · **窗口无法打开。** 在图形会话的终端中运行，并检查 `echo "$DISPLAY"` 和 `xauth info`。启动脚本会向容器传递当前显示器的认证 cookie。
- **Docker** · **Ollama 报错或首次响应较慢。** 运行 `docker compose logs --tail 40 ollama` 和 `docker compose exec ollama ollama list`。CPU 首次加载模型需要一些时间。请求失败后，原有场景会保留。
- **形状与预期不符。** 明确数量、单位和接触位置。检查轮廓和网格后，选择需要修改的部件。

反馈问题时请提供输入描述、网格配置和复现步骤。[GitHub Issues](https://github.com/glitchykid/xtrifid/issues) · [架构与 Docker 测试](docs/architecture.md)
