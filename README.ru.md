# Xtrifid

Создавайте редактируемые 3D-модели по тексту или референсам в GTK. Проверяйте сетку, моделируйте движение ткани, волос и жидкостей и назначайте отдельным деталям материалы и рельеф поверхности. Размеры задаются в метрах. Интерфейс на русском языке.

В коллекции для Xtrifid 0.7.0 восемь готовых сцен Game Ready. Среди них лунный меч, ретробластер, парадный пистолет, веер из павлиньих перьев, болотный монстр, фонарь, орбитальное заклинание и морская волна. Откройте любой файл `.xtri`, чтобы изменить его детали или материалы. [Посмотреть модели](https://github.com/glitchykid/xtrifid/blob/main/examples/art-studies/gallery.jpg) · [Скачать XTRI и GLB](https://github.com/glitchykid/xtrifid/releases/download/art-studies-1/xtrifid-art-studies.zip)

## Исполняемый файл для Linux

Скачайте файл для Linux x86‑64. Нужны glibc 2.39 или новее, графический сеанс и OpenGL 3.3. Подходят Linux Mint 22 и Ubuntu 24.04. Python, GTK и CPU‑версия Ollama уже входят в сборку. [Скачать Xtrifid для Linux](https://github.com/glitchykid/xtrifid/releases/latest/download/xtrifid-linux-x86_64)

В каталоге загрузки выполните команды ниже. После выдачи права на выполнение файл можно открывать и двойным щелчком.

```sh
chmod +x ./xtrifid-linux-x86_64
./xtrifid-linux-x86_64
```

Чтобы сразу открыть сохранённый проект, передайте путь к нему при запуске. Каждый проект откроется в отдельном окне. Предпросмотр, числовая правка и экспорт в OBJ или GLB работают без интернета.

```sh
./xtrifid-linux-x86_64 "model.xtri"
```

Для сложных описаний и текстовых правок студия ищет запущенную локальную Ollama, включая сервис Xtrifid в Docker для Linux. Если его нет, запускается встроенный движок на CPU. Если при первом запросе отсутствуют веса, нажмите **Скачать модель**. Для `qwen3.5:4b` потребуется около 3,3 ГБ. После загрузки повторите запрос. Встроенный движок сохраняет веса в `~/.ollama/models` для дальнейшей работы без интернета. Через `OLLAMA_MODELS` можно выбрать другую папку весов, через `OLLAMA_URL` указать сервер, а через `XTRIFID_MODEL` выбрать модель с поддержкой структурированного вывода.

## Запуск из исходников в Docker

Нужны Docker Engine с Compose, Git, `xauth` и графический сеанс X11 или XWayland с OpenGL 3.3. Подходит программный рендеринг Mesa. При первом запуске будут загружены образы контейнеров. Для произвольных описаний также понадобятся веса модели (около 3,3 ГБ для Qwen). Приложение проверено на CPU с 16 ГБ оперативной памяти.

```sh
git clone https://github.com/glitchykid/xtrifid.git
cd xtrifid
./studio
```

Скрипт запускает Ollama и открывает студию. Когда для запроса понадобятся веса, нажмите **Скачать модель**. Следующие сеансы используют сохранённые в Docker-томе веса. Текст запросов остаётся в локальной сети Docker. Другую модель Ollama с поддержкой структурированного вывода можно выбрать через `XTRIFID_MODEL` перед запуском `./studio`. Команда `docker compose down` останавливает сервис.

## Создание и правка

1. Опишите форму, размер и соединение деталей. Например, попросите настольное зеркало с круглым диском и овальным основанием. Для первого запуска без весов введите `сделай человека`. Укажите профиль **Game Ready** или **Для рендера**, затем в поле **Детализация** выберите **Низкая**, **Средняя** или **Высокая**. Нажмите **Создать модель**.
2. Перетаскивание вращает модель, колесо меняет масштаб, щелчок выбирает деталь. **Сетка** показывает рёбра. **К детали** (F) приближает выбранную деталь, **К лицу** показывает лицо человека крупным планом, Home возвращает общий вид. Стрелки вращают модель.
3. Чтобы изменить размеры, центр или поворот детали, нажмите **Применить значения**. У человека разверните **Анатомия и поза**, выберите нейтральное, мужское или женское телосложение, задайте позу или измените пропорции отдельных областей, включая уши, нос, губы и подбородок и нажмите **Применить к телу**. **Изменить деталь** применяет текстовую правку, **Отменить действие** возвращает предыдущее состояние.
4. **Сохранить** записывает редактируемый проект `.xtri`, **Открыть** восстанавливает его, **Экспорт OBJ** сохраняет текущую сетку. Исполняемый файл сохраняет данные прямо в выбранную папку. В Docker выбирайте `/exports`, чтобы файл остался в каталоге `./exports` на компьютере.

## Форма и поверхность

**Low Poly** включает гранёный стиль независимо от профиля и выбранной детализации. Криволинейные примитивы получают меньше сегментов. Чтобы вернуть сглаживание, снимите флажок. Плоские грани и запечённые кадры сохраняют свою топологию. Числа сегментов в таблице профилей указаны для обычного стиля.

Для ветвящейся органики опишите ствол, ответвления, их пропорции и направления, например коралл с тремя сужающимися ветвями. В разделе **Узлы формы** выберите узел по имени и измените его локальное положение или радиус. Ветви соединены общей замкнутой поверхностью.

## Симуляция

Выберите опорную деталь и раскройте **Физика**. Доступны ткань, волосы, водная поверхность и объёмная жидкость. Полотно ложится на выбранный предмет, а у выбранного плаща сохраняется крепление на плечах. У прядей закреплены корни. Водная поверхность воспроизводит волны в прямоугольном бассейне. Порция объёмной жидкости падает на предмет и растекается под действием гравитации.

Задайте ветер и гравитацию, нажмите **Воспроизвести**, остановите движение или выберите кадр на шестисекундной шкале (180 шагов). **Запечь кадр в модель** сохраняет видимую геометрию в проекте для экспорта OBJ. Плащ заменяется деформированной сеткой, остальные эффекты добавляют деталь. Изменение можно отменить. Столкновения рассчитываются по упрощённым формам. Скорость воспроизведения зависит от детализации и процессора. Чтобы сохранить результат после закрытия проекта, запеките нужный кадр.

## Материалы Game Ready

Выберите деталь и раскройте **Текстура детали**. Доступны дерево, камень, ткань, кожа, металл и гладкое покрытие. Задайте палитру, узор, масштаб, зерно и разрешение от 128 до 1024 пикселей. **Назначить** создаёт карты без сети. **Новый вариант** меняет зерно. **Создать по описанию (ИИ)** подбирает параметры через локальную Ollama, например по запросу «полированная латунь с мелкими царапинами». Рецепт можно сохранить в проекте и изменить позже.

Для нового материала в Game Ready включён флажок **PBR-материал**. Выставьте **Шероховатость** (0–1), **Металличность** (0–1) и **Сила рельефа** (0–2), затем нажмите **Назначить**. При нулевой силе карта нормалей плоская. В предпросмотре свет выявляет переплетение ткани, поры кожи и волокна дерева. Силуэт и число треугольников сохраняются. Чтобы добавить рельеф ранее сохранённой цветовой текстуре, включите для неё PBR.

**Экспорт GLB** в профиле Game Ready записывает один файл с индексированными треугольниками, UV, касательными и текстурами. Базовый цвет хранится в sRGB. Карта нормалей использует касательное пространство OpenGL +Y. В линейной карте зелёный канал хранит шероховатость, синий — металличность. При переносе OBJ скопируйте и соседнюю папку `xtrifid-materials-…`. В игровом профиле для PBR-деталей в ней есть отдельные PNG нормалей, шероховатости и металличности. Если импортёр MTL прочитал только цвет, назначьте эти три карты как линейные данные (Non-Color). В OBJ для рендера сохраняются цветовая карта и четырёхугольники.

[Три материала в GLB](https://github.com/glitchykid/xtrifid/releases/download/v0.7.0/material-study.glb) · [Редактируемый проект](https://github.com/glitchykid/xtrifid/releases/download/v0.7.0/material-study.xtri)

## Модели по референсам

Выберите детализацию и нажмите **По референсам…**. В режиме **Силуэты** загрузите фронтальный PNG или JPEG. При наличии добавьте вид того же объекта справа. Подойдут прямые проекции на прозрачном или однотонном фоне. Белым показана выделенная маска. Укажите высоту в метрах. Второй вид задаёт глубину своими пропорциями. Для одного вида значение по умолчанию — 55% ширины, его можно заменить вручную. Для округлых предметов можно включить **Округлить сечения**. Программа оценит поперечную форму и толщину тонких выступов. В разделе **Силуэты модели** кистью добавьте или сотрите фрагмент и нажмите **Применить силуэты**.

Для обычной фотографии выберите **Фото с ИИ**. Уменьшенные изображения получит выбранная модель Ollama с поддержкой зрения. Она построит приближённую редактируемую сцену по видимому объекту. Текстовое уточнение помогает выбрать предмет. Скрытые поверхности модель достраивает по предположению. Режим силуэтов работает без весов и сети. Один файл может занимать до 16 МиБ и содержать до 24 мегапикселей. В Docker положите картинки в `exports/` на компьютере и выберите их в `/exports`. В примере с эспрессо сохранилось отверстие в ручке чашки. Чашечка ложки получилась плоской. [Фотография, проект и OBJ](https://github.com/glitchykid/xtrifid/releases/download/v0.6.0/photo-example.zip)

## Правка одного угла или кольца

Выберите деталь и раскройте **Контур детали**. Щёлкните по точке на чертеже или задайте её номер в поле **Вершина**. В окне 3D подсветится соответствующее ребро, кольцо или полюс. Перетащите точку, задайте две локальные координаты в метрах и нажмите **Применить координаты** либо введите команду, например «Увеличь радиус этой точки на 5 мм, высоту сохрани».

У параллелепипеда и выдавленного контура точка задаёт вертикальное ребро в локальной плоскости XY. У цилиндра, конуса, втулки и тела вращения радиус и Z задают кольцо или полюс. После первой правки примитив становится выдавленным контуром или телом вращения. Остальные точки сохраняют положение в пространстве. Если границы детали изменятся, её центр пересчитается. Отмена возвращает исходную форму. Сферы и торы редактируются целиком. Существующие проекты XTRI открываются напрямую.

У криволинейной оболочки откройте **Поперечные сечения**. Выберите кольцо, задайте высоту, радиусы по X и Y или центр в метрах и нажмите **Применить сечение**. Изменится подсвеченное кольцо. Остальные сохранят своё положение.

## Профили геометрии

| Профиль | Сетка |
| --- | --- |
| Game Ready | Треугольники с согласованным обходом. На окружность приходится 8, 16 или 32 сегмента в зависимости от детализации. У параллелепипеда 8 вершин и 12 треугольников. |
| Для рендера | На окружность приходится 24, 48 или 64 сегмента. На регулярных участках сохраняются полосы четырёхугольников. На полюсах, кромках и сложных торцах используются треугольники, где это нужно. |

Локальная языковая модель может составить сцену из 48 именованных деталей и описывать криволинейные оболочки с эллиптическими сечениями, которые смещаются, расширяются и сужаются по высоте. Размеры и указанные опоры задают положение деталей. Форму незнакомого объекта может потребоваться поправить.

В основе фигуры взрослого человека лежит анатомическая сетка MakeHuman. Уши, губы, веки, пальцы и туловище образуют единую поверхность кожи. У глаз отдельная геометрия. Запрос «человек» создаёт фигуру без одежды. Плащ и капюшон указывайте явно. Чтобы менять пропорции, выберите тело. Тело и каждый предмет одежды могут иметь собственный материал.

## Детализация и ресурсы компьютера

Выберите низкую, среднюю или высокую детализацию. В двух профилях у тела шесть вариантов плотности сетки. Проект запоминает выбор. Если в проекте есть PBR-материал или сохранённая UV-развёртка запечённой ткани, студия использует формат XTRI 5. Остальные проекты сохраняются в формате 4. Студия открывает файлы версий 1–5. Базовые запросы на фигуру работают без весов. Для свободных описаний и текстовых правок нужны веса Ollama.

Редактируемые примеры · [Человек](https://github.com/glitchykid/xtrifid/releases/download/v0.5.0/human.xtri) · [Корпус мыши](https://github.com/glitchykid/xtrifid/releases/download/v0.5.0/mouse-shell.xtri) · [Настольное зеркало](https://github.com/glitchykid/xtrifid/releases/download/v0.5.0/table-mirror.xtri) · [Коралл](https://github.com/glitchykid/xtrifid/releases/download/v0.6.0/coral.xtri) · [Физика](https://github.com/glitchykid/xtrifid/releases/download/v0.6.0/physics-examples.zip) · [Ваза с текстурой](https://github.com/glitchykid/xtrifid/releases/download/v0.6.0/textured-vase.zip) · [Силуэты и чайник](https://github.com/glitchykid/xtrifid/releases/download/v0.6.0/reference-example.zip)

Перед предпросмотром и экспортом Xtrifid оценивает число треугольников, доступную оперативную память и ограничения контейнера Linux. Программа оставляет запас для рабочего стола. Верхняя граница сцены — 150 000 треугольников после триангуляции. Если выбранный уровень не помещается, текущая модель остаётся доступной. Можно уменьшить детализацию или выбрать Game Ready. При открытии файла студия предложит подходящий уровень, если он есть. Для ИИ отдельно ограничиваются размер загружаемой модели, потоки CPU и длина контекста. Нагрузка других программ тоже влияет на устойчивость системы.

## Устранение проблем

- **Исполняемый файл не открывается.** Проверьте право на выполнение, наличие графического сеанса и версию glibc командой `ldd --version`. Если Linux сообщает об отсутствующей версии `GLIBC`, воспользуйтесь инструкцией для Docker выше.
- **Загрузка весов прервалась.** Проверьте свободное место на диске сервера и соединение с интернетом. Если в сообщении указана ошибка TLS, проверьте системные доверенные сертификаты на сервере. Затем снова нажмите **Скачать модель**. Первая генерация на CPU может занять несколько минут.
- **Docker** · **Чёрное окно предпросмотра или `MESA: error: Failed to attach to x11 shm`.** Если вы клонировали репозиторий, выполните `git pull --ff-only` и снова запустите `./studio`. При установке из архива используйте версию 0.2.1 или новее. Скрипт пересоберёт образ с драйвером Mesa, который умеет выводить кадры при изолированной общей памяти Docker.
- **Docker** · **Окно не открывается.** Запустите приложение из графического сеанса, проверьте `echo "$DISPLAY"` и `xauth info`. Скрипт передаёт контейнеру cookie текущего дисплея.
- **Docker** · **Ошибка Ollama или долгий первый запрос.** Проверьте `docker compose logs --tail 40 ollama` и `docker compose exec ollama ollama list`. Загрузка модели в память на CPU занимает время. После ошибки предыдущая сцена остаётся доступной.
- **Неожиданная форма.** Задайте количество деталей, единицы измерения и места стыков. Проверьте силуэт и сетку, затем исправьте выбранную деталь.

При обращении приложите запрос, профиль и шаги воспроизведения. [GitHub Issues](https://github.com/glitchykid/xtrifid/issues) · [Архитектура и проверки в Docker](docs/architecture.md)
