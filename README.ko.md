# Xtrifid

소품이나 사람을 글로 설명하고 GTK의 3D 뷰에서 메시를 보며 원하는 부품을 수정할 수 있습니다. 형상은 미터 단위로 편집하는 정적 모델입니다. 화면 언어는 러시아어입니다.

## Linux 실행 파일

x86-64 Linux에서 glibc 2.39 이상, 그래픽 데스크톱, OpenGL 3.3이 필요합니다. Linux Mint 22와 Ubuntu 24.04는 이 배포판 요건을 충족합니다. 실행 파일에는 Python, GTK, CPU용 Ollama가 들어 있습니다. [Linux용 Xtrifid 다운로드](https://github.com/glitchykid/xtrifid/releases/latest/download/xtrifid-linux-x86_64)

다운로드한 폴더에서 다음 명령을 실행하세요. 실행 권한을 부여한 후에는 파일을 두 번 클릭해 열 수 있습니다.

```sh
chmod +x ./xtrifid-linux-x86_64
./xtrifid-linux-x86_64
```

저장한 프로젝트 경로를 인수로 넘기면 프로젝트마다 새 창에서 열립니다. 오프라인에서도 미리보기, 수치 편집, OBJ 내보내기를 사용할 수 있습니다.

```sh
./xtrifid-linux-x86_64 "model.xtri"
```

복잡한 설명과 텍스트 편집에는 Linux의 Xtrifid Docker 서비스를 포함해 실행 중인 로컬 Ollama를 먼저 찾습니다. 사용할 수 있는 서비스가 없으면 내장 CPU 엔진을 시작합니다. 첫 요청에서 가중치가 없다는 메시지가 뜨면 **Скачать модель**를 눌러 `qwen3.5:4b`(약 3.3 GB)를 받은 후 요청을 다시 보내세요. 내장 엔진은 `~/.ollama/models`에 가중치를 보관해 이후에는 오프라인에서도 생성할 수 있습니다. `OLLAMA_MODELS`로 가중치 폴더를, `OLLAMA_URL`로 서버를, `XTRIFID_MODEL`로 구조화 출력을 지원하는 모델을 지정할 수 있습니다.

## Docker로 소스에서 실행하기

Docker Engine과 Compose, Git, `xauth`, OpenGL 3.3을 지원하는 X11 또는 XWayland 데스크톱이 필요합니다. Mesa 소프트웨어 렌더링도 사용할 수 있습니다. 처음 실행하면 컨테이너 이미지를 받습니다. 자유로운 설명으로 생성할 때는 모델 가중치도 필요합니다(Qwen은 약 3.3 GB). 메모리 16 GB의 CPU 환경에서 검증했습니다.

```sh
git clone https://github.com/glitchykid/xtrifid.git
cd xtrifid
./studio
```

스크립트가 Ollama를 시작하고 스튜디오를 엽니다. 가중치를 요청하면 **Скачать модель**를 누르세요. 다음부터는 Docker 볼륨에 저장한 가중치를 사용합니다. 입력한 설명은 로컬 Docker 네트워크에서 처리합니다. 구조화된 출력을 지원하는 다른 Ollama 모델을 쓰려면 `./studio` 실행 전에 `XTRIFID_MODEL`을 설정하세요. 서비스를 종료할 때는 `docker compose down`을 실행하세요.

## 모델 생성과 수정

1. 형태, 치수, 부품이 맞닿는 위치를 설명하세요. 예를 들어 둥근 거울판과 타원형 받침대가 달린 탁상거울을 요청할 수 있습니다. 가중치 없이 처음 시험할 때는 `make a person`을 입력하세요. **Game Ready** 또는 **Для рендера**를 선택하고 **Детализация**에서 **Низкая**(낮음), **Средняя**(중간), **Высокая**(높음) 중 하나를 고른 뒤 **Создать модель**을 누르세요.
2. 드래그해 회전하고 휠로 확대하거나 축소합니다. 클릭해 부품을 선택하세요. **Сетка**는 모서리를 표시합니다. **К детали**(F)는 선택한 부품을, **К лицу**는 얼굴을 확대합니다. Home으로 전체를 보고 방향키로 회전하세요.
3. 치수, 위치, 회전각을 바꾸고 **Применить значения**를 누르세요. 인물의 경우 **Анатомия и поза**에서 성인 체형(중성·남성·여성)과 자세를 선택하거나 귀, 코, 입술, 턱 등의 크기를 바꾼 뒤 **Применить к телу**를 누르세요. **Изменить деталь**로 문장 수정을 적용하고 **Отменить действие**으로 실행을 취소합니다.
4. **Сохранить**는 편집 가능한 `.xtri`를 저장하고 **Открыть**는 저장한 프로젝트를 엽니다. **Экспорт OBJ**는 현재 메시를 내보냅니다. 실행 파일은 선택한 폴더에 바로 저장합니다. Docker에서는 `/exports`를 선택하면 호스트의 `./exports`에 저장됩니다.

## 모서리나 링 하나 수정하기

부품을 선택하고 **Контур детали**를 펼치세요. 단면도의 점을 클릭하거나 **Вершина**에서 번호를 고르면 해당 모서리, 링 또는 극점이 3D 뷰에 강조 표시됩니다. 점을 드래그하거나 로컬 좌표 두 개를 미터 단위로 입력한 뒤 **Применить координаты**를 누르세요. “이 점의 반지름을 5 mm 늘리고 높이는 유지해 줘”와 같은 문장으로도 수정할 수 있습니다.

직육면체와 돌출 형상에서는 로컬 XY 평면의 점이 수직 모서리를 정합니다. 원기둥, 원뿔, 관, 회전체에서는 반지름과 Z 좌표가 링이나 극점을 정합니다. 처음 수정하면 기본 도형이 돌출 형상이나 회전체로 변환됩니다. 다른 제어점은 공간상의 위치를 유지하고 형상의 범위가 달라지면 부품 중심이 재계산됩니다. 실행 취소로 원래 형상을 복원할 수 있습니다. 타원체와 토러스는 부품 단위로 편집합니다. 기존 XTRI 프로젝트도 그대로 열 수 있습니다.

곡면 외형은 **Поперечные сечения**를 열어 고리를 선택하세요. 높이, X/Y 반지름, 중심 좌표를 미터로 입력한 다음 **Применить сечение**를 누르세요. 강조된 고리만 바뀌며 나머지 고리는 원래 위치에 유지됩니다.

## 메시 프로필

| 프로필 | 메시 |
| --- | --- |
| Game Ready | 정점 순서가 일관적인 삼각형 메시입니다. 원주는 낮음·중간·높음 순으로 8, 16, 32분할하며 직육면체는 정점 8개와 삼각형 12개로 구성됩니다. |
| Для рендера | 원주는 24, 48, 64분할하며 규칙적인 곡면에서는 사각형 띠를 유지합니다. 극점, 테두리, 복잡한 끝면 등에는 필요에 따라 삼각형을 사용합니다. |

로컬 언어 모델은 이름이 붙은 부품을 최대 48개까지 조립합니다. 높이에 따라 타원 단면의 중심과 너비를 바꿔 굽은 외형을 구성할 수 있습니다. 치수와 지지 관계에 따라 부품을 배치합니다. 생소한 물체는 원하는 형태로 다듬어야 할 수 있습니다.

성인 인체는 MakeHuman 해부학 메시를 사용합니다. 귀, 입술, 눈꺼풀, 손가락과 몸통은 하나의 연속된 피부 표면이고 안구는 별도 형상입니다. 인물만 요청하면 옷을 입지 않은 인체가 생성됩니다. 망토와 후드는 명시하세요. 몸을 선택하면 비율을 수정할 수 있습니다. OBJ는 재질과 애니메이션 리그가 없는 정적 형상을 저장합니다.

## 세부 수준과 시스템 자원

상세도는 낮음, 중간, 높음 중에서 선택하세요. 두 프로필에 걸쳐 인체 메시의 해상도는 여섯 가지입니다. 프로젝트에 선택이 저장되며 버전 1과 2도 열립니다. 기본 인체 명령은 오프라인에서 작동합니다. 자유로운 설명과 문장 수정에는 Ollama 가중치가 필요합니다.

편집 가능한 예제 · [사람](https://github.com/glitchykid/xtrifid/releases/download/v0.5.0/human.xtri) · [마우스 외장](https://github.com/glitchykid/xtrifid/releases/download/v0.5.0/mouse-shell.xtri) · [탁상거울](https://github.com/glitchykid/xtrifid/releases/download/v0.5.0/table-mirror.xtri)

미리보기와 내보내기 전, 사용 가능한 RAM과 Linux 컨테이너 제한을 바탕으로 삼각형 수를 추산합니다. 데스크톱용 메모리를 남기며 장면의 상한은 삼각형 환산 150,000개입니다. 선택한 수준이 한도를 넘으면 기존 장면을 유지합니다. 세부 수준을 낮추거나 Game Ready를 선택하세요. 저장된 파일을 열 때는 사용 가능한 수준을 선택할 수 있습니다. 추론에는 모델 크기, CPU 스레드 수, 컨텍스트 길이 제한이 별도로 적용됩니다. 다른 프로그램의 부하도 시스템에 영향을 줍니다.

## 문제 해결

- **실행 파일이 열리지 않을 때.** 실행 권한과 그래픽 세션을 확인하고 `ldd --version`으로 glibc 버전을 살펴보세요. 필요한 `GLIBC` 버전이 없다는 메시지가 나오면 위의 Docker 실행 방법을 이용하세요.
- **가중치 다운로드가 끊길 때.** 서버의 디스크 여유 공간과 인터넷 연결을 확인하세요. TLS 오류가 표시되면 서버에서 신뢰하는 CA 인증서도 확인하세요. 그런 다음 **Скачать модель**를 다시 누르세요. CPU에서 첫 모델을 생성하는 데 몇 분이 걸릴 수 있습니다.
- **Docker** · **미리보기가 검게 나오거나 `MESA: error: Failed to attach to x11 shm` 오류가 표시될 때.** Git으로 설치했다면 `git pull --ff-only`로 업데이트한 뒤 `./studio`를 다시 실행하세요. 압축 파일로 설치했다면 0.2.1 이상을 사용하세요. 실행 스크립트가 이미지를 다시 빌드하면 새 Mesa 드라이버가 Docker의 공유 메모리가 격리된 상태에서도 화면을 표시합니다.
- **Docker** · **창이 열리지 않을 때.** 그래픽 세션의 터미널에서 실행하고 `echo "$DISPLAY"`와 `xauth info`를 확인하세요. 스크립트가 현재 디스플레이의 인증 쿠키를 전달합니다.
- **Docker** · **Ollama 오류가 발생하거나 첫 응답이 느릴 때.** `docker compose logs --tail 40 ollama`와 `docker compose exec ollama ollama list`를 확인하세요. CPU에서 모델을 처음 불러올 때 시간이 걸립니다. 요청이 실패해도 이전 장면은 유지됩니다.
- **원하는 형상이 나오지 않을 때.** 수량, 단위, 접촉 위치를 명시하세요. 윤곽과 메시를 확인한 뒤 해당 부품을 골라 수정하세요.

문제를 제보할 때는 입력 문장, 프로필, 재현 절차를 함께 적어 주세요. [GitHub Issues](https://github.com/glitchykid/xtrifid/issues) · [설계 및 Docker 테스트](docs/architecture.md)
